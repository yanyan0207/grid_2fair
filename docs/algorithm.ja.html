行単位の探索で a(16)〜a(19) を求める

n×n の格子のマスをいくつか塗り、塗っていないマスがどれも上下左右でちょうど 2 個の塗ったマスに接するようにします。塗るマスの最小個数が a(n) です。行単位の DFS から始め、予算と下界で枝を切る行単位の DP（src/dp.rs）で、OEIS に載っている a(15) の先、a(16)〜a(19) まで求めました。最後に、同じ下界を DFS（src/dfs.rs）に入れると DP より速くなることが分かり、今は DFS が既定です。その仕組みを順に説明します。

結果

a(16) = 102、a(17) = 115、a(18) = 128、a(19) = 141

このページを作った時点で OEIS に載っていたのは a(15) までです（a(12)〜a(15) は Bert Dobbelaere が 2021 年に計算）。a(12)〜a(15) は同じプログラムで再現でき、その先の 4 項を求めました。各値について、次の 2 つを確かめています。

  • a(n) − 1 個では塗れない: 下界から a(n) − 1 までのすべての予算で、DP が「解なし」を返した。
  • a(n) 個で塗れる: 盤面を復元し、全マスの条件を Board::is_valid で確かめた。

流れ

DFS から DP へ進み、また DFS に戻る

  1. 行単位の DFS: 上から 1 行ずつ決める。2 行決まると次の行の大半が強制される（考え方 1〜4）。最初の版は下界を持たず、n = 9 で 16 秒、n = 10 は 2 分で終わらなかった。
  2. DP（メモ化）: 先の探索は直前の 2 行だけで決まるので、同じ 2 行に来た経路をまとめる。
  3. 予算と下界: 「予算以下で塗れるか」を判定し、残りの行に最低限必要な塗り数で枝を切る。これで a(15) が数秒になった。
  4. メモリの削減: 表は 2 枚だけ持つ。盤面は、向きを交互に変える DP で復元する。左右対称で状態を半分にする。
  5. 先読み: 状態を表に入れる前に次の行の強制マスを求め、行き止まりと予算超過を捨てる。表の 8〜9 割が次の行で行き止まりになる状態だった。
  6. DFS に戻る: 予算、下界、先読み、左右対称をそのまま DFS に入れると、DP より速く、メモリも経路の n 行分だけで済んだ。
考え方 1

1 行をビット列で表し、上から順に決める

各行を u64 の整数で表します。列 c を塗ったら c ビット目を 1 にします。上の行から 1 行ずつ「この行のどのマスを塗るか」を決めていく深さ優先探索です。

あるマスの条件（塗っていないなら塗った隣がちょうど 2 個）が判定できるのは、上・左・右・下の 4 マスが全部決まったときです。行 r のマスなら、行 r+1 を決めた時点で判定できます。

考え方 2

2 行決まると、下の行の大半が強制される

行 r とその上の行 r−1 が決まったとします。行 r の塗っていないマスについて、上・左・右にある塗ったマスの数を s とすると、真下に必要な塗りの数は 2 − s です。下は 1 マスしかないので、これは 0 か 1 でなければなりません。

つまり行 r の塗っていないマスの真下は、塗るかどうかが 1 通りに決まります。行 r の塗ったマスには条件がないので、その真下だけが自由に選べます。

考え方 3

自由なのは「塗ったマスの真下」だけ

右の図では行 r（黄色の帯）の塗っていないマスから、行 r+1 の強制マス（橙）が決まっています。点線枠は行 r の塗ったマスの真下で、ここだけは塗っても塗らなくても構いません。

そこで次の行の候補は「強制マス ∪ 自由マスの部分集合」になります。自由マスが k 個なら候補は 2k 通りで、行全体の 2n 通りよりずっと少なくなります。

部分集合はビット演算 sub = (sub - 1) & cur で全部列挙します。

考え方 4

s の判定は 1 行まとめてビット演算で

上の行を a、左隣を並べた b = cur << 1、右隣を並べた c = cur >> 1 とすると、各ビットで a, b, c のうち何個が 1 かを一度に計算できます。s が 1 のビットは「下を塗る」、2 のビットは「下を塗らない」、0 や 3 のビットがあれば行き止まりです。

pub fn forced_below(full: u64, up: u64, cur: u64) -> Option<u64> {
    let a = up;
    let b = (cur << 1) & full;
    let c = cur >> 1;
    let all3 = a & b & c;
    let ones = (a ^ b ^ c) & !all3;                       // s = 1
    let twos = ((a & b) | (b & c) | (a & c)) & !all3;  // s = 2
    let unpainted = !cur & full;
    if unpainted & !(ones | twos) != 0 {
        return None;                                     // s = 0 か 3 がある
    }
    Some(unpainted & ones)                               // 下に塗りが必要なマス
}
考え方 5（dfs.rs）

予算を決めて、進む前に枝を切る

  • 予算: 「予算 B 個以下で塗れるか」を調べます。B は下界から 1 つずつ上げ、初めて塗れた B が a(n) です。下界の作り方は、後の「予算と下界」で説明します。
  • 進む前の判定: 次の行の候補ごとに、その行の強制マスまで求めてから進むかを決めます。行き止まり（上・左・右の塗りが 0 個か 3 個の白マスがある）、最後の行なのに盤の外に塗りが要る、「ここまでの塗り数 + 残りの行に最低限必要な塗り数」が予算を超える、のどれかなら進みません。
  • 1 行目と左右対称: 1 行目の上は盤の外なので、上の行を 0 として扱います。解を左右反転しても解なので、1 行目は左右反転したもの以下の行だけ試します。
  • 探索ノード数: 判定を通って行に進んだ回数です。全部の予算で合計します。cargo run --release が表示する nodes と同じ数え方です。

最初の DFS が遅かった理由

同じ状態を何度も解いている

行 k+1 から下で何ができるかは、行 k−1 と行 k の 2 行だけで決まります。それより上の行は条件の確認が済んでいて、先には「そこまでの塗り数」としてしか影響しません。

DFS で一意なのは「行 0 から今の行までの経路」です。直前の 2 行が同じで、上だけが違う経路はたくさんあり、その先はまったく同じ探索になります。DFS はそれを毎回やり直していました。

n = 5、3 行目まで。行 1, 2 が同じで行 0 だけ違う経路が 8 通りある（4 通りを表示）

行0 #..#.   行0 .###.   行0 ####.   行0 .#..#
行1 #####   行1 #####   行1 #####   行1 #####
行2 .....   行2 .....   行2 .....   行2 .....
塗り数 7    塗り数 8    塗り数 9    塗り数 7
  • n = 5 で 3 行目まで: DFS の経路 1,045 本に対し、異なる状態は 357 個。
  • n = 9 で 6 行目まで: DFS の経路は約 6.7 億本、異なる状態はどの深さでも 8 万個以下。

ここから DP に進みましたが、後で分かったことに、一番の原因は下界がなかったことでした。最初の DFS は「ここまでの塗り数 + 次の行の強制マス数」が暫定最良以上かどうかしか見ておらず、残りの行に必要な塗り数を考えていませんでした。下界を入れると、同じ状態に別の経路で来ることもほとんどなくなります（「DFS に戻る」の節）。

DP

直前 2 行を状態にして、行ごとに幅優先で進める

状態を (上の行, 今の行) とし、行 k で到達できる状態と、そこまでの最小塗り数を表にします。行 k の表から、強制マスと自由マスの部分集合で行 k+1 の表を作ります。同じ状態が何度生まれても、塗り数の小さい方だけを残します。

次の表は今の表だけから作れます。なので、持つ表は「今の行」と「次の行」の 2 枚で足ります。DFS は今の経路しか覚えないのでメモリはほぼ使いませんが、DP は 1 行分の状態を全部持つ代わりに、重複をなくしています。

予算と下界

残りの行に最低限必要な塗り数で枝を切る

最小値を直接探す代わりに、予算 B を決めて「B 個以下で塗れるか」を判定します。行 k までの塗り数 c と、残りの行に最低限必要な塗り数（下界）の和が予算を超える状態は捨てます。

// 行 k までの塗り数 c の状態を残す条件
c + anchored[n - 1 - k] <= budget

1 行ずつでは下界にならないので、帯で考える

「塗った行・空の行・塗った行」の横縞なら、空の行のマスは上下 2 つが塗られていて条件を満たします。なので 1 行単体に必要な塗り数は 0 です。一方、空の行が 2 行続くことはできません。連続した何行かの帯には、必ず塗りが要ります。

  • Sh: 高さ h の帯で、上下の外側の行を自由に塗れるとみなしたときの最小塗り数。どんな解でも、連続する h 行にはこれ以上塗られている。
  • Bh: 盤の下端に接する高さ h の帯の最小塗り数（下の外側は塗れない）。
  • 残りの m 行を「下端の帯 1 つ + 自由な帯いくつか」に分けて最小値を足せば、下界になる。分け方の中で一番大きいものを使う。

帯の最小値は、帯を左から右へ 1 列ずつ決める DP で計算します。行単位の強制の計算を 90° 回したもので、状態は (左の列, 今の列) の 4h 通りです。h = 9 まで使っています。

n = 16 で、下端に接する残り m 行の下界（m = 0..16）
0, 6, 13, 19, 27, 32, 39, 44, 50, 56, 61, 67, 73, 79, 85, 91, 96

16 行全体の下界は 96 で、答えの 102 との差は 6 しかありません。最適値ぎりぎりの予算で判定すると、上の方で少し塗りすぎた状態はすぐ予算オーバーになります。

状態数の山

状態は上から 2 行目あたりで一番多くなる

n = 16、予算 102 で、各行の表に残った状態の数です（左右対称を使う前の計測）。

棒の長さは対数目盛です。

  • 序盤は組み合わせが増える: 行 0 の状態は行 0 の値だけで決まり、最大 2n 個。行 1、行 2 で「2 行の組」になって一気に増える。
  • 進むほど枝刈りがきつくなる: 序盤は残りの行が多く、帯をつないだ下界が甘いので、少し塗りすぎた状態も生き残る。進むにつれて塗り数が正確に積み上がり、残りの行の下界も正確になる。
  • 最後にまた少し増える: 「最後の行に強制マスがあってはいけない」は最後の行でしか確かめられないので、下端でつながらない状態がそこまで残る。

表を 2 枚にしても、この一番大きい表は持つ必要があります。メモリの上限はここで決まります。

盤面の復元

向きを交互に変えて DP を繰り返す

表を 2 枚しか持たないと、最後にわかるのは最小値と最後の 2 行だけです。それより上の行は忘れています。

  1. 確定した下の 2 行から出発し、上下を反転して DP を回す。最後に上の 2 行が確定する。
  2. 確定した上の行から出発し、下の確定した行につながる 2 行を確定させる。
  3. 向きを交互に変えて、全行が確定するまで繰り返す。

どの回も出発点が 1 状態に固定されるので、序盤の状態の膨らみが起きません。最初の DP の数十分の 1 以下で済み、メモリが最初の判定を超えることもありません。

左右対称

左右反転で重なる状態を 1 つにまとめる

状態 (上の行, 今の行) と、2 行とも左右反転した状態は、先の探索が鏡写しになるだけで最小塗り数も同じです。次の状態を作るたびに、反転したものと比べて小さい方をキーにします。下界も左右対称なので、枝刈りの判定は変わりません。

判定の DP の最後の状態が鏡写しの方でも、解を左右反転すればその 2 行で終わる解になるので、そのまま復元の出発点に使えます。復元の DP は両端が固定されていて左右対称ではないので、まとめません。

n = 17対称性なし左右対称あり
予算 114（解なし）の状態数の最大27,360,60913,682,042
予算 115（解あり）の状態数の最大109,314,29654,660,545
合計時間31.3 秒16.3 秒

上下反転は、上から一方向に進む DP では使えません。回転は行という構造を壊すので使えません。

先読み

表に入れる前に、次の行の強制マスを見る

行 k+1 の状態 (cur, down) を作った時点で確かめているのは、行 cur の条件だけです。行 down の白マスが条件を満たせるかは、次の行を作るときに初めて分かります。計測すると、表に入れた状態の 8〜9 割が、次の行で行き止まりになる状態でした。

  • 行き止まりを入れない: 表に入れる前に forced_below(cur, down) を求め、None なら入れない。
  • 強制マスを下界に足す: 次の行の強制マスは必ず塗るので、「塗り数 + 強制マス数 + その先の行の下界」が予算を超える状態も入れない。

どちらも、次の段階で必ず捨てられる状態を 1 段早く捨てているだけなので、答えは変わりません。

DFS に戻る

同じ枝刈りなら、DFS の方が速い

予算、帯の下界、先読み、左右対称を、そのまま DFS に入れたのが今の src/dfs.rs です。状態の表を持たないので、メモリは今の経路の n 行分だけです。n = 15 まで、どれも 0.3 秒以内で終わります。

  • 解ありの予算で、最初の解が見つかった時点で止まる: DP は解ありの予算でも全行の表を最後まで作り、そこに時間の大半を使っていました。
  • 盤面の復元が要らない: 今の経路がそのまま解です。
  • 同じ状態に来ることが少ない: 下界と先読みで経路が大きく減るので、DP のように同じ状態をまとめなくても、調べ直しがほとんど起きません。

最初の DFS が遅かったのは、深さ優先という方式のせいではなく、下界がなかったためでした。

まだやっていないこと
