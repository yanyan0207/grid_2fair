# grid_2fair

[English](README.md) | 日本語

[OEIS A344719](https://oeis.org/A344719) の項を計算する Rust プログラムです。

n×n の格子のいくつかのマスを塗り、塗っていない全てのマスが上下左右でちょうど 2 個の塗ったマスに隣接するようにします。このとき塗るマスの最小個数が a(n) です。

## 結果

OEIS に載っているのは a(1)〜a(15) です（2026-10-04 時点。a(12)〜a(15) は Bert Dobbelaere による）。このプログラムで a(1)〜a(15) を再現し、その先を求めました。

| n | a(n) | 出どころ |
|--:|--:|---|
| 1〜15 | 1, 2, 5, 8, 11, 17, 21, 28, 35, 42, 51, 60, 69, 80, 91 | OEIS（再現） |
| 16 | 102 | このプログラム |
| 17 | 115 | このプログラム |
| 18 | 128 | このプログラム |
| 19 | 141 | このプログラム |
| 20 | 156 | このプログラム |
| 21 | 171 | このプログラム |
| 22 | 186 | このプログラム |

各 a(n) は次の 2 点で確かめています。

- a(n) 個の解を見つけ、全マスの条件を `Board::is_valid` で検証した。
- 予算 a(n)−1 で全部の塗り方を調べ、解がないことを示した。a(n)−1 個で塗れないので、それより少なくても塗れない。

a(16)〜a(22) は、下のアルゴリズム（DP、DFS、stripes-dfs）のうち 2 つ以上で、それぞれ独立に同じ値を得ています。

これらの値から見えてくる規則は、次の「予想」の節にまとめています。

## 予想

求めた値と解から、次の 2 つの予想が立ちます。どちらも証明はありません。

**予想 1（値の式）** n ≥ 7 で、

```
a(n) = ⌈(n+2)² / 3⌉ − 6
```

- n = 7〜22 の 16 個の値すべてと一致する。言い換えると、n = 8 以降の階差が 7, 7, 7, 9, 9, 9, 11, 11, 11, 13, 13, 13, 15, 15, 15 と、同じ値を 3 回ずつ繰り返す。
- 主要項の n²/3 には簡単な理由がある。塗っていないマスはちょうど 2 個の塗ったマスに接し、塗ったマスが接するマスは最大 4 個なので、全体の 3 分の 1 以上を塗る必要がある。(n+2)² の形と −6 は、端の影響と考えられる。

**予想 2（解の形）** どの n ≥ 6 にも、上下 2 行と左右 2 列を除いて、全部の行が周期 3 の斜めの縞（行ごとに決まる s について、c ≡ s (mod 3) の列だけを塗る）になる最適解がある。

- n = 6〜22 では、DFS が見つけた最適解がこの形になっている。これらの n でこの形の最適解が存在することは確かめたが、すべての最適解が縞になるかは調べていない。
- 既定のアルゴリズム stripes-dfs は、この予想を前提に設計している（「アルゴリズム」の節）。

## 使い方

リリースビルドで実行してください。デバッグビルドは桁違いに遅くなります。

```sh
cargo run --release -- 16                # n = 16 を解く
cargo run --release -- 3 --to 22         # n = 3 から 22 まで順に解く
cargo run --release -- 16 --algo dfs     # アルゴリズムを選ぶ（stripes-dfs | dfs | dp | brute、既定は stripes-dfs）
```

出力は、探索の経過、解の盤面（`#` が塗ったマス）、塗り数、時間です。n を 1 つ解くたびに、そこまでの結果を b-file の形式（`n a(n)`）と、カンマ区切りの DATA の形式でまとめて出すので、途中で Ctrl-C で止めても結果をそのまま貼れます。
n の上限は stripes-dfs、dfs、dp が 30、brute が 7 です。brute が実用的なのは n = 5 までです。

## アルゴリズム

図と計測、動くデモつきの説明は [docs/algorithm.ja.html](docs/algorithm.ja.html) をブラウザで開いてください。要点は次の通りです。

- 行をビット列で表し、上から 1 行ずつ決める。2 行決まると次の行の大半が強制される（`forced_below`）。
- 予算 B を決めて「B 個以下で塗れるか」を判定する。残りの行の下界は、高さ 9 までの帯の最小塗り数（列方向の DP）をつないで作る。
- 行に進む前に次の行の強制マスを求め、行き止まりと「塗り数 + 下界」が予算を超える状態を切る（先読み）。左右反転で重なるものは片方だけ調べる。
- **stripes-dfs（既定）**: 最適解は、端の近くを除くと周期 3 の斜めの縞になっている。まず、上下 2 行と左右 2 列を除いて行を縞に限った盤面の中で、解を作る。真ん中の 2 行を選び、そこから上下の端へ 1 行ずつ伸ばし、結果を覚えて使い回す。作った解の塗り数を U として、予算 U−1 の DFS で全部の塗り方を調べ、最小だと証明する。DFS が解を見つけたら、その塗り数を新しい U にする。
  このアルゴリズムは、「予想」の節の予想 2 を前提に設計している。答えはこの予想に依存しない。最小だという証明は、縞の制限なしの DFS で必ず行うからである。依存するのは速さだけで、縞の解が a(n) に届かなければ、DFS が解ありの予算を探索することになり、dfs と同程度の時間がかかる。
- **dfs**: 予算を下界から 1 つずつ上げ、初めて塗れた予算を a(n) にする。今の経路だけをメモリに持つ。
- **dp**: 同じ探索を、状態（今の行, その真下の強制マス）の表で幅優先に進める。表は 2 枚だけ持ち、盤面はあとで復元する。答えの確認と計測に使う。

## 計測

Core i7-12700F、メモリ 32GB、シングルスレッドでの値です。

| n | stripes-dfs（既定） | dfs | dp |
|--:|--:|--:|--:|
| 19 | 2.2 秒 | 5.3 秒 | 13.2 秒 |
| 20 | 12.2 秒 | 54 秒 | |
| 21 | 46.4 秒 | 168 秒 | |
| 22 | 164 秒 | 552 秒 | |

stripes-dfs で縞の解を作る段階は、n = 22 でも 5 秒以内です。残りの時間は、予算 a(n)−1 で全部の塗り方を調べる探索です。dfs と stripes-dfs が使うメモリは、今の経路の分だけです。

## 構成

| ファイル | 役割 |
|---|---|
| `src/stripes_dfs.rs` | stripes-dfs（既定）。縞の解を作り（`construct`）、DFS で最小だと証明する |
| `src/stripes.rs` | 縞の行。判定（`is_striped`）と一覧（`rows`） |
| `src/dfs.rs` | 予算付きの行単位 DFS。進む前の判定（`admit`）、再帰（`rec`） |
| `src/dp.rs` | 予算付きの行単位 DP。（行, 強制マス）の表の DP（`forward`）、判定（`search`）、復元（`reconstruct`） |
| `src/bound.rs` | 帯の下界（`strip_min`、`lower_bounds`）。DFS と DP の両方で使う |
| `src/row.rs` | 行の共通の操作。強制マス（`forced_below`）、状態のキー、左右反転 |
| `src/brute.rs` | 総当たり。答え合わせ用 |
| `src/board.rs` | 盤面と、条件を満たすかの検証 |
| `src/lib.rs` | OEIS の既知の値 |
| `src/main.rs` | コマンドライン |

## テスト

```sh
cargo test --release
```

stripes-dfs、DFS、DP の答えが互いに、また n = 15 までの OEIS の値と一致すること、小さい n で総当たりとも一致すること、縞の制限の幅を変えても答えが変わらないこと、下界が答えを超えないこと、答えより 1 小さい予算では解なしになること、左右対称でまとめても判定が変わらないことを確かめます。
