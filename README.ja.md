# grid_2fair

[English](README.md) | 日本語

[OEIS A344719](https://oeis.org/A344719) の項を計算する Rust プログラムです。

n×n の格子のいくつかのマスを塗り、塗っていない全てのマスが上下左右でちょうど 2 個の塗ったマスに隣接するようにします。このとき塗るマスの最小個数が a(n) です。

## 結果

OEIS に載っているのは a(1)〜a(15) です（2026-10-04 時点。a(12)〜a(15) は Bert Dobbelaere による）。このプログラムで a(1)〜a(15) を再現し、その先を求めました。

| n | a(n) | 出どころ |
|--:|--:|---|
| 1〜15 | 1, 2, 5, 8, 11, 17, 21, 28, 35, 42, 51, 60, 69, 80, 91 | OEIS（再現） |
| 16 | 102 | このプログラム |
| 17 | 115 | このプログラム |
| 18 | 128 | このプログラム |
| 19 | 141 | このプログラム |
| 20 | 156 以上 | 予算 155 まで解なし（途中） |

各 a(n) は次の 2 点で確かめています。

- 下界から a(n)−1 までのすべての予算で DP が「解なし」を返した。つまり a(n)−1 個では塗れない。
- a(n) 個の解を復元し、全マスの条件を `Board::is_valid` で検証した。

階差は n = 8 以降 7, 7, 7, 9, 9, 9, 11, 11, 11, 13, 13, 13 と、同じ値が 3 回ずつ続いています。

## 使い方

リリースビルドで実行してください。デバッグビルドは桁違いに遅くなります。

```sh
cargo run --release -- 16            # n = 16 を解く
cargo run --release -- 3 --to 18     # n = 3 から 18 まで順に解く
cargo run --release -- 16 --algo dp  # アルゴリズムを選ぶ（dfs | dp | brute、既定は dfs）
```

出力は、予算ごとの判定結果、解の盤面（`#` が塗ったマス）、塗り数、時間です。DFS は探索ノード数も、DP は復元の経過も表示します。
n の上限は dfs と dp が 30、brute が 7 です。brute が実用的なのは n = 5 までです。

## アルゴリズム

図と計測、動くデモつきの説明は [docs/algorithm.ja.html](docs/algorithm.ja.html) をブラウザで開いてください。要点は次の通りです。

- 行をビット列で表し、上から 1 行ずつ決める。2 行決まると次の行の大半が強制される（`forced_below`）。
- 予算 B を決めて「B 個以下で塗れるか」を判定し、予算を下界から 1 つずつ上げる。初めて塗れた予算が a(n)。
- 残りの行の下界は、高さ 9 までの帯の最小塗り数（列方向の DP）をつないで作る。
- 行に進む前に次の行の強制マスを求め、行き止まりと「塗り数 + 下界」が予算を超える状態を切る（先読み）。
- 左右反転で重なるものは片方だけ調べる。
- 既定の DFS は、今の経路だけをメモリに持つ。DP は 1 行分の状態をハッシュ表に持ち、表は 2 枚だけにして、盤面は向きを交互に変える DP で復元する。

## 計測

Core i7-12700F、メモリ 32GB、シングルスレッドでの値です。

DFS（既定）:

| n | 合計時間 | 探索ノード数 |
|--:|--:|--:|
| 13 | 0.16 秒 | 18,431 |
| 14 | 0.21 秒 | 197,804 |
| 15 | 0.29 秒 | 466,183 |

時間の大半は、最初に下界を計算する 0.1 秒ほどです。

DP:

| n | 合計時間 | 状態数の最大 | ピークメモリ |
|--:|--:|--:|--:|
| 16 | 0.48 秒 | 184,106 | |
| 17 | 6.3 秒 | 3,488,013 | |
| 18 | 7.1 秒 | 2,026,563 | |
| 19 | 21.5 秒 | 6,754,091 | 345 MB |

DP は n が 1 増えるごとに必要なメモリが 5〜8 倍になります。DFS が使うメモリは今の経路の分だけです。

## 構成

| ファイル | 役割 |
|---|---|
| `src/dfs.rs` | 予算付きの行単位 DFS（既定）。進む前の判定（`admit`）、再帰（`rec`） |
| `src/dp.rs` | 予算付きの行単位 DP。表 2 枚の DP（`forward`）、判定（`search`）、復元（`reconstruct`） |
| `src/bound.rs` | 帯の下界（`strip_min`、`lower_bounds`）。DFS と DP の両方で使う |
| `src/row.rs` | 行の共通の操作。強制マス（`forced_below`）、状態のキー、左右反転 |
| `src/brute.rs` | 総当たり。答え合わせ用 |
| `src/board.rs` | 盤面と、条件を満たすかの検証 |
| `src/lib.rs` | OEIS の既知の値 |
| `src/main.rs` | コマンドライン |
| `examples/profile.rs` | DP の状態の内訳を行ごとに表示する計測プログラム |

## テスト

```sh
cargo test --release
```

DFS と DP の答えが互いに、また n = 15 までの OEIS の値と一致すること、小さい n で総当たりとも一致すること、下界が答えを超えないこと、答えより 1 小さい予算では解なしになること、左右対称でまとめても判定が変わらないことを確かめます。
